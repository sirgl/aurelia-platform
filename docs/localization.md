# Localization

**Everything the player reads comes from message bundles (`assets/lang/<code>/*.ftl`), English is the source of truth, and anyone can add a language by dropping a folder next to the settings file, without recompiling.** State: 2026-10-20 (branch `i18n/localization`). This document is the reference for developers and translators; the inventory, the numbers and the status of each language are at the end.

## 2. Design and decision

**Decision.** A key-based message catalogue in our own small crate (`platform/crates/i18n`), with a message syntax that is a subset of Mozilla's Fluent (`.ftl`), instead of the `fluent` crates, ICU MessageFormat or a RON/TOML table.

| Question | Answer |
|---|---|
| Source of truth | The English bundle (`assets/lang/en/`). Every key used in code must exist there (a test fails otherwise); every other bundle is measured against it. |
| Arguments | Named: `{ $turn }`, never positional. The order of words belongs to the language, so a translator can move a placeholder. |
| Plurals | CLDR categories per language (`plural.rs`): `one`/`other` (en, de, es, fr: 0 and 1 are `one` in French), `one`/`few`/`many`/`other` (ru, uk, pl), none (zh, ja, ko), Arabic with six. The message chooses the variant: `{ $n -> [one] .. *[other] .. }`. A bundle missing a form its language needs is an error in the linter. Exact numbers (`[0]`) and text selectors (`[feminine]`) give zero-forms and gender/case. |
| Numbers, dates | `{ NUMBER($n) }` groups and separates decimals by language (1,234.5 / 1.234,5 / 1 234,5); `{ DATE($d) }` writes a numeric date in the language's order. A small table, not a locale database. |
| Fallback | requested tag -> shorter tags (`pt-BR` -> `pt`) -> `en`; Chinese by script (`zh-CN`, `zh` -> `zh-Hans`; `zh-TW` -> `zh-Hant` -> `zh-Hans`). A key missing in the chosen language shows its English text, never a key or a crash. |
| Language switch | The Settings screen (Game page) lists the languages by their own names; the choice is saved as `language = auto|<tag>` in `settings.cfg` and applies at once. `auto` follows the system: `LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG`, macOS `AppleLanguages`; the web and Android layers pass the browser/OS list through `shell::language::set_os_locales`. `AURELIA_LANG=<tag>` overrides for one run (screenshots, tests). |
| Bundles | Built in: every `assets/lang/<code>/*.ftl` is compiled in by `platform/crates/i18n/build.rs` (a new folder is picked up by a rebuild; text only, so a few hundred KB). External: `<config dir>/lang/<code>/*.ftl` is read at start-up; it adds a language or overrides single messages of a built-in one. No network, no threads. |
| Validation | `i18n-check lint` (and the same code at start-up for external bundles, which only logs): syntax, duplicate keys, keys not in English, placeholders that do not exist in the original or are dropped, plural forms the language needs or can never use, `{ references }` that name nothing, empty texts, missing `meta.name`. Nothing panics. |
| Content text | Rule data (names, descriptions of units, buildings, technologies, policies, wonders, events) keeps its English or neutral text and stays out of the rules hash. Its translations are messages with stable keys `<module>.<kind>.<id>.<field>` (`classic.unit.warrior.name`, `lal.law.conscription.name`); the UI asks `i18n::content(..., fallback)` and gets the rule data's own text when no bundle has the key. |
| Module wording | `key@scope` overrides `key` for one game module: Lands & Laws says "faction" where the shell says "nation" (`shell.observer.nation-label@lal`). The shell enters the module's scope; a language without the override shows its own plain text. |
| Terminology (the project owner's rules) | The unit of time is "turn" in every text, in both games: Russian *khod*, French tour, German Zug, Spanish turno, Japanese ターン, Chinese 回合; "round"/Russian *raund*/Runde/ronda/ラウンド are forbidden (a test fails on them). "Your own move" is its own pair of messages (`shell.turn.your-move`, `shell.turn.not-your-move`). The Russian word *tsivilizatsiya* ("civilization") is forbidden: *natsiya* ("nation") is used for Classic nations and *derzhava* ("power") for Lands & Laws factions; English "nation" / "faction". The game is never called by the original game's name in any text. |
| Test language | `en-XA`: English with accents, expanded about 35% and put in brackets, derived from `en` at run time. Plain letters on screen are unlocalized text; a missing closing bracket is clipped text. |

**Why our own crate and not Fluent.** The `fluent` crates would also work (they build for wasm), but they bring about fifteen dependencies (`fluent-bundle`, `fluent-syntax`, `intl-memoizer`, `intl_pluralrules`, `unic-langid`, `self_cell`...), a memoizer built around `RefCell`/`Send` choices that matters for a UI that renders on one thread and builds on others, and a loader layer we would still have to write (fallback chain, external folders, validation). ICU4X is heavier still. A RON/TOML table has no syntax for plurals or arguments. What we need is small and exact: about 1,500 lines of Rust with no dependency, which builds for wasm32 and Android as it is, and whose message syntax is the Fluent subset translators already know (editors highlight `.ftl`; Weblate, Pontoon and Crowdin read it). Differences from Fluent, so nobody is surprised: keys may contain dots and `@scope`; there are no terms (`-term`), attributes or custom functions; only `NUMBER` and `DATE` exist. Moving to `fluent-bundle` later is a loader swap, not a rewrite of the bundles.

**Why English is the source of truth.** The game's rules and the Lands & Laws text were written in Russian and English mixed; one language has to define what a key means. English has the most translators and the shortest plural system; every other bundle is checked against it. Russian is migrated into a `ru` bundle like any other.

**What is deliberately not done.** Right-to-left scripts and complex shaping (Arabic, Hebrew, Indic): egui does not lay them out; the plural table knows Arabic but no bundle ships. Text in art images (section 11). Voice and audio.

## 3. How it works

* `platform/crates/i18n` — the library. `syntax` parses `.ftl`; `plural`, `numfmt`, `locale` hold the language tables; `catalog` holds the sources of all languages and the `Translator` (a fallback chain); `state` is the process-wide active language with the lookups `t!`, `tf!`, `i18n::content`; `validate` and `tool` are the linter; `pseudo` makes `en-XA`; `external` reads the player's folder; `extract` finds the keys used in code.
* `t!("shell.end-turn")` returns `&'static str` (one copy per key and language, kept for the life of the process, so it fits struct fields and `&'static str` returns). `tf!("shell.hud.health", current = hp, max = max)` returns a `String`. A key that no bundle has is shown as the key and noted in `i18n::missing_keys()`.
* The shell: `platform/crates/client/src/shell/words.rs` resolves the plain shell words (`ShellWords`) from the catalogue once per language, catalogue and module scope; texts with numbers and names are asked with `tf!` where they are drawn. `shell/language.rs` picks the language (`auto` or a tag), installs the player's bundles and feeds the selector; `shell/settings.rs` persists `language`.
* Language threads: tests and tools use `i18n::with_language("ru", || ...)`, which changes the language of the current thread only, so parallel tests do not disturb each other. The module's scope is set globally by the app (`i18n::set_scope`) and per thread by `i18n::enter_scope`.

## 4. Adding a language

**Built-in** (part of the game): create `assets/lang/<code>/` with these files and rebuild.

1. `meta.ftl`: `meta.name` (the language's own name, as the player's list shows it) and `meta.english`.
2. `STATUS`: one line; its first word is the state (`machine-drafted`, `reviewed`, `community`) and the Settings screen tells the player what it means.
3. The message files, named like the English ones (`shell.ftl`, `classic-*.ftl`, `lal-*.ftl`, `content-*.ftl`, `glossary.ftl`). Start from a template: `cargo run --release -p aurelia-i18n --bin i18n-check -- template <code>` writes every English file with the English text marked `# TODO` where there is no translation yet.
4. `cargo run --release -p aurelia-i18n --bin i18n-check -- lint` and `cargo test -p aurelia-i18n`: zero errors.
5. If the script needs glyphs the shipped fonts lack (section 8), add a font.

**External** (a community pack, no recompile): put the same folder in the config directory — `~/.config/aurelia/lang/<code>/` on Linux, `~/Library/Application Support/Aurelia/lang/<code>/` on macOS, `%APPDATA%\Aurelia\lang\<code>\` on Windows (or `$AURELIA_CONFIG_DIR/lang/<code>/`). Restart the game; the language appears in Settings -> Game -> Language marked "custom bundle". Problems are printed to the log (errors) and never stop the game; run `i18n-check lint --dir <config dir>/lang` to see them all. A folder named after a built-in language overrides single messages of it (fix a typo without waiting for a release).

## 5. Writing messages

**Keys** are lowercase words joined by dots and hyphens: `<area>.<screen or kind>.<thing>[.<part>]`. Areas: `shell` (menu, settings, HUD frame, observer), `classic` and `lal` (a module's screens: `lal.laws.status-adopted`), `sandbox`, `glossary`, `rule` (rule texts), content (`classic.unit.warrior.name`). A key says what the text is, not what it says; never reuse a key for two meanings; `.label`, `.help`, `.tip`, `.title`, `.empty` are the usual last parts. A file's keys sit under the prefix of the Rust file that shows them.

**Arguments** are named by what they are (`$city`, `$turns`, `$gold`), not by position.

```
shell.saves.saved = Saved on turn { $turn }
shell.hud.turns = { $n ->
    [one] { $n } turn
   *[other] { $n } turns
}
```

**Plurals.** Write the forms your language needs; the linter says which. Russian: `[one]` 1, 21, 31..; `[few]` 2-4, 22-24..; `[many]` 0, 5-20, 25-30..; `*[other]` fractions. German/English/Spanish: `one` and `other`. French: `one` covers 0 and 1. Chinese/Japanese: no select, just the text. Always write the number into the text as an argument; do not assume `1` means "a".

**Genders and cases.** Pass the property as an argument from code only where the original language needs it; a select on text covers it: `{ $owner -> [feminine] her *[other] his }`. Messages for one thing in several grammatical roles are separate keys (`.nominative`, `.of`); do not build sentences from pieces in code.

**Numbers and dates.** Use `{ NUMBER($n) }` for quantities that may exceed 999 or have decimals; plain `{ $n }` writes digits as given. `{ DATE($d) }` takes a date argument.

**Do not** put markup, units of layout or key names a player does not read into messages; keycaps (`Esc`, `Tab`) stay as they are on the keyboard. A message ends without a trailing space; it may contain `\n` by continuing on an indented line. Write a literal `{` as `{"{"}`.

**References.** `{ glossary.city }` inserts another message. Use it for the core terms so they stay consistent; avoid it where the language inflects the term.

## 6. Content names and descriptions

Rule data stays English and neutral and is part of the rules fingerprint (`kernel/src/rules/rows.rs` hashes every `name`): **changing a data name changes the rules hash and breaks old saves and replays, so a translation must never replace a data name.** Translations are messages:

* key: `<module>.<kind>.<id>.<field>` with `i18n::content_key`: the id is lowercased, a namespace before `:` (`core:`, `lal:`) and a table path (`unit/`) are dropped, an `UPPER_SNAKE` id loses its kind prefix, `_` becomes `-`: `core:unit/anti-aircraft-gun` -> `classic.unit.anti-aircraft-gun.name`; `lal:UNIT_SCOUT` -> `lal.unit.scout.name`; fields: `name`, `desc`, `story`, `title`... The kinds of the Classic ruleset are `unit`, `building`, `tech`, `policy`, `promotion`, `belief`, `nation`, `great-person`, `era`, `terrain`, `feature`, `resource`, `improvement`, `natural-wonder`, `city-state`, `project`, `specialist`, `handicap`, `religion`, `city-state-type`; those of Lands & Laws, with the Rust id to pass for each, are in `lands/docs/localization-lal-content.md`.
* lookup: `i18n::content("classic", "unit", row.key, "name", &row.name)`; the last argument is the rule data's text, used when no bundle has the key.
* Lands & Laws in the UI: `lands/crates/lal-ui/src/content.rs` has one helper per kind (unit, building, tech, improvement, law, path, event with choices, faction, leader, era, ruin, wonder, project, programme, tribe, calendar year) that asks `i18n::content("lal", ...)` with the pack's row id and falls back to the data text. A city founded in a game stores the name of the pack's pool (Russian) in the save; `view::city_name` finds the stored name in the faction's pool and shows the interface language's name of the same slot (a numeric suffix " 2" is kept; a renamed or captured city is shown as stored), and `Session::localize_city_labels` does the same for the labels the map draws. The save and the game state are never touched.
* Classic in the UI: `classic/crates/classic-ui/src/game/names.rs` (`named`) is the one door for unit, building, technology, policy, resource and nation names.
* the English bundle holds a message for every rule row (generated: `python3 classic/tools/i18n/gen_content_classic.py` for Classic, `lands/tools/i18n/gen_content_lal.py` for Lands & Laws; a test of `lal-content` fails when a row has no text key), so `en` is complete and a diff shows when data changes; the data's own text is only the last resort for modded rules.

## 7. Glossary and translators

`assets/lang/<code>/glossary.ftl` holds about 85 core terms (city, nation, technology, policy, unit types, yields, terrain...). Translate it first and use the same word everywhere. The terms follow the vocabulary players of that language know from games of the genre (Unciv's terminology where it is established; its files are not copied). `i18n-check` prints the glossary table of all languages (`platform/docs/localization-glossary.md`).

**Terminology that is not up to the translator** (the project owner's rules, enforced by `platform/crates/i18n/tests/bundles.rs::the_forbidden_words_are_not_in_the_bundles`): the unit of time is *turn* in every text of both games (ru *khod*, fr tour, de Zug, es turno, ja ターン, zh 回合; "round", ru *raund*, Runde, ronda, ラウンド fail the test), the player's own move is its own message pair (`shell.turn.your-move`, `shell.turn.not-your-move`), Classic *nations* are ru *natsiya*/nation/Nation/nación/国家 and Lands & Laws *factions* ru *derzhava*/faction/Fraktion/facción/勢力, and the Russian word *tsivilizatsiya* and its translations (civilisation, Zivilisation, civilización, 文明) never appear. `python3 platform/tools/i18n/turn_terminology.py` rewrote the old texts and message keys once (idempotent; rerun it on a branch that still says "round").

Translator workflow: 1. `i18n-check template <code>` 2. translate the `# TODO` entries (keep arguments, keep the plural forms of your language) 3. `i18n-check lint` 4. try it: `AURELIA_LANG=<code>` in the environment, or Settings -> Language 5. look at the long texts on the main screens: German text runs about 30% longer than English, CJK is shorter but taller. `en-XA` shows the same problem in English. Send the folder (or a pull request).

## 8. Fonts and scripts

* The interface font is Inter (Latin, Cyrillic, Greek; `platform/assets/fonts/Inter-*.ttf`, 0.8 MB) after egui's own fonts. Latin-extended letters of French, German, Spanish and the others are covered.
* Chinese and Japanese: `platform/assets/fonts/NotoSansSC-Subset.otf` and `NotoSansJP-Subset.otf`, subsets of Noto Sans CJK Regular (SIL OFL, see `platform/assets/fonts/OFL.txt`) cut to the glyphs the bundles use by `python3 platform/tools/i18n/subset_fonts.py` (needs `fontTools`; rerun it whenever the zh-Hans or ja bundles gain characters, and commit the result). `client::shell::theme::language_fonts(tag)` names the files of a language (Japanese first for `ja`, Simplified Chinese first for `zh`: the two draw the same Han characters differently); `install_fonts` appends them behind the other fonts of both families when the language changes (a browser gets the files on demand and the shell retries each frame until they have arrived).
* A character the subsets lack (an external bundle with rare hanzi) shows as a box. The remedy is to rerun the subsetter with the characters added, or to ship a full font; the shell does not read system fonts (a CJK font is 15-20 MB).
* Not supported: right-to-left scripts and complex shaping (Arabic, Hebrew, Indic scripts, Thai line breaking): egui lays text out left to right glyph by glyph. A bundle in such a language would load and be validated but would not display correctly.
* Line breaking: egui wraps at spaces; Chinese and Japanese have none, so a long CJK message wraps at the container width in the middle of a word group (egui breaks between any two CJK characters). Keep CJK messages short; there are no punctuation-rule (kinsoku) guarantees.

## 9. Checking

* `sh platform/tools/i18n-lint.sh`: the ratchet (no UI crate gains raw user-visible string literals beyond `platform/tools/i18n-literals.baseline`; `--update` lowers it) and `i18n-check keys` / `lint`. Part of CI.
* `cargo run --release -p aurelia-i18n --bin i18n-check -- coverage | lint [--missing] [--dir D] | keys [--unused] | template <code>`.
* Tests: `cargo test --release -p aurelia-i18n` (syntax, plurals, fallback, external bundles, validator, every key used in code exists in `en`, every built-in bundle is error-free); `-p aurelia-client` (shell words in each language, settings, HUD layout in `en`, `ru`, `de`, `en-XA`).

## 10. Migrating code

For each raw string literal the scanner finds (`python3 platform/tools/i18n-scan.py --list <file>`):

1. Choose the key (section 5); the prefix is the file's.
2. Add the English text to the area's `assets/lang/en/<area>.ftl` (this is the source). If the code had Russian text, move it to the same key in `assets/lang/ru/<area>.ftl` and write the English as a translation of it.
3. Replace the literal: `"Text"` -> `t!("key")` (`&'static str`; usable wherever a `&str` is, but not in `const`/`static` initialisers or in patterns: make those functions or tables of keys); `format!("Health {}/{}", a, b)` -> `tf!("key", current = a, max = b)`; a counted noun -> one message with a plural select, the number passed as `n`. Never build a sentence from translated parts.
4. A text chosen by an enum value (`match reason { A => "...", B => "..." }`) keeps its `match`, returning `t!("...")`.
5. Run `cargo test -p <crate>` (the snapshots render English) and `sh platform/tools/i18n-lint.sh`; lower the baseline with `sh platform/tools/i18n-lint.sh --update`.
6. Text that must stay raw (log lines, ids, persisted values) gets `// i18n-ok: <reason>` on its line.

## 11. Text in art

Nothing in the art needs translating. The pictures of the art pack (menu and screen backgrounds, city, policy and civic emblems, unit, building, resource and action atlases, leader portraits, ornaments: 247 pictures with prompts under `classic/assets/visual/generated/`) were generated with prompts that forbid text: 167 of the prompt files say "no text / no letters / no lettering" in so many words, the others describe a picture without writing; a look at the menu, city, civics and research art and at the menu screenshot found none. Every label over art (names under emblems, the menu title block `AURELIA`, the cover texts) is drawn by the interface from the catalogue. The word "AURELIA" in the cover is the product name and is not translated. If a future picture carries lettering it cannot be localized without regenerating it (one picture: a prompt and a pass of review, about half an hour per picture); the rule for artists: no text in pictures.

## 13. Russian only in assets/lang/ru

The project was written in Russian first, and the repository is public in English. The rule:

* **Russian text lives in `assets/lang/ru/` and nowhere else** (plus the private archive `ru/`, below). Documents, comments, test names, data files, scripts and tools are English. A Russian user text in code or in rule data is a message key with an English source and a Russian entry in `assets/lang/ru/` (section 6).
* **`ru/` is a private archive of the original Russian files** (documents, old working output, the originals of translated scripts, at the same relative path: `ru/docs/x.md` is the original of `docs/x.md`). It is not part of the public repositories (`ru/README.md`). Nothing reads it: no build, test or tool may depend on a file below `ru/`.
* **Guard:** the rule "Russian only in the Russian locale" is kept by a private check that lives in the private folder `ru/` of the monorepo; it is not part of this repository and no build, test or CI step of it depends on it.
* **Adding Russian text elsewhere is a failure of the guard.** Translate it; if the Russian original is worth keeping, copy it to `ru/<same path>` in the same commit.
* `platform/tools/i18n/gen_glossary.py` does not generate the Russian glossary: edit `platform/assets/lang/ru/glossary.ftl` by hand.
